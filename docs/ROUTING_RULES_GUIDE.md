# 分流规则入门与原理

## 1. 一条流量是怎么被分流的

设备的连接进入网关后(Mode A 由 nftables TPROXY 拦截,Mode B / C 由主路由引过来),Xray 按**规则集里的规则顺序**逐条匹配,第一条命中的规则决定去向;没有命中的走末尾的**兜底策略**(直连或默认代理)。规则在「分流」页维护,改完即生效(协调器渲染 Xray 规则并热更新,改了结构性配置才重启)。

同一套规则同时渲染给 Mosdns:动作是代理(默认代理 / 指定节点 / 出站组)的域名和 geosite 规则,会汇成"代理域名列表",这些域名的解析走远端上游(经节点);其它域名中,`geosite:cn` 走本地上游,剩下走远端上游。所以改规则不需要再单独改 DNS。

## 2. 规则集与顺序

- 规则集是有序的分组;集内规则也有序。整体匹配顺序 = 规则集顺序 × 集内顺序。
- **内置默认集**永远排第一、不能删、不能改名。新库会种子化三条规则:`geoip:private → 直连`、`geosite:cn → 直连`、`geoip:cn → 直连`。它们可以停用或删除,但请记住它们在最前:如果你在后面的集里写 `geosite:cn → 某国内节点`,会被种子的直连规则遮蔽,永远匹配不到。
- 规则列表最后固定显示两行:**兜底**(未命中规则的流量走直连还是默认代理)和**节点失效策略**(节点全部探测失败时退回默认出站还是拦截)。它们就是网络配置里的 LAN 默认策略和失效策略,只在这里改。
- 拖拽可以调整规则集和规则的顺序;停用的规则保留但不渲染。

## 3. 匹配类型

| 类型 | 值 | 说明 |
|---|---|---|
| `domain` | `example.com` | 只匹配这个名字(Xray `full:`) |
| | `**.example.com` | 根域和所有子域(Xray `domain:`)。这是最常用的写法 |
| | `*.example.com` | 根域和一级子域(正则) |
| `geosite` | `cn`、`google`、`category-ads-all`、`anthropic`… | GeoData 的域名集合,输入时从已安装的 GeoData 里多选 |
| `geoip` | `cn`、`google`、`private`、`telegram`… | GeoData 的 IP 集合;匹配**连接目标 IP**,对域名目标要先解析 |
| `ip` | `1.2.3.4` 或 `10.0.0.0/8` | IPv4 / IPv6 地址或 CIDR |

域名能被域名规则匹配,靠的是嗅探(TLS SNI / HTTP Host)和 Mosdns 的解析:Mode A 下 Xray 对拦截到的连接做 routeOnly 嗅探,只用来匹配、不改目的地址,所以 access log 里看到的目标仍是 IP。

「分流 → GeoData 查询」可以反查一个域名或 IP 属于哪些 geosite / geoip 标签,以及某个标签里有哪些条目;观测页的连接也带这些标签。

## 4. 动作

| 动作 | 去向 |
|---|---|
| 直连 | `direct` 出站(freedom),带 fwmark 2,不会再被拦截 |
| 默认代理 | 默认节点;没有默认节点时是全部启用节点的 leastPing 均衡;一个节点都没有时直连 |
| 拦截 | 黑洞(`block`) |
| 指定节点 | 某个节点 |
| 出站组 | 故障转移组或负载均衡组 |

## 5. 节点与出站组

- 节点:VLESS(含 REALITY)、VMess、Trojan、Shadowsocks、SOCKS、HTTP、WireGuard。可从分享链接批量导入。每个节点每 30 秒经探测入站访问 `cp.cloudflare.com` 一次,延迟和错误显示在节点页和总览。
- WireGuard 节点默认走**内核隧道**(每个节点一个 `ergw-xxxx` 接口、一张 `3xx` 路由表、`fwmark 0x1xx` 规则),吞吐比 Xray 用户态高一倍以上;WARP 这类带 reserved 字段的、或内核没有 wireguard 模块的,自动退回用户态。
- 出站组:
  - **故障转移**:按成员顺序,主成员探测健康就用它,挂了切下一个。Xray 侧是带 observatory 的 balancer,主成员为 selector,其余为 fallback。
  - **负载均衡**:`leastPing`(最低延迟)、`leastLoad`(最稳定)、`random`、`roundRobin`;探测失败的成员不会被选中。
- 从 1.x 导入时,`ha-A-B` 策略会变成一个故障转移组「HA A → B」。

## 6. 设备策略与绕过目标(仅 Mode A)

- **设备策略**:按来源 MAC 或 IP 覆盖规则:`proxy`(强制全部走默认代理)、`direct`(强制直连)、`reject`(丢弃)。在 nftables 层生效,先于 Xray。
- **绕过目标**:目的 IP / CIDR 永远直连、不进 Xray,用来保护管理入口、堡垒机、中继等。备注可在列表里点击修改。
- Mode B / C 下这两项不下发:流量是主路由引过来的,在网关上绕过会形成环路。

## 7. 三种模式下的差异

| | Mode A | Mode B | Mode C |
|---|---|---|---|
| 进入网关的流量 | 设备的全部流量 | 只有代理域名(Fake-IP `198.18.0.0/16`)的流量 | 只有规则解析出的真实 IP 的流量 |
| 域名规则 | 嗅探 + DNS | 由 Fake-IP 直接对应域名,最准 | 周期解析成 IP 宣告(OSPF),解析结果变了会更新 |
| geoip 规则 | 直接生效 | 对 Fake-IP 不生效(目标不是真实 IP) | 展开成前缀宣告 |
| 直连 / 拦截规则 | 在网关上生效 | 不经过网关的流量本来就直连 | 同 B |
| 兜底策略 | 决定未命中的流量 | 只影响被引过来的流量 | 同 B |

Mode C 下每条域名规则都要解析展开,规则多时留意「OSPF 宣告参数」和主路由的路由表容量;`geoip:!cn` 这类巨大集合不适合做 Mode C 的宣告来源。

## 8. DNS 怎么配合

- 本地上游(国内域名)、远端上游(其它域名,经节点),默认都是 DoH / DoT。
- 劫持 LAN DNS:经过网关的所有 53 端口查询都交给 Mosdns(目的是私网 DNS 的除外),设备手动指定 8.8.8.8 也一样;DoT(853)被拒绝,设备退回普通 DNS。
- ECS 客户端子网:网关出口在境外时,把国内网段作为 EDNS Client Subnet 发给本地上游,国内站返回就近 CDN。
- 内网域名转发:后缀 → 指定上游,排在缓存和分流之前、不走代理。
- IPv6 过滤:全部或仅代理域名不返回 AAAA,避免设备绕开只接管 IPv4 的 TPROXY。
- 记录解析结果:观测页据此把连接的 IP 目标标成域名。

## 9. 用 Trace 验证

「分流」页顶部输入 `www.google.com`、`8.8.8.8`、`192.168.1.10` 之类,得到:命中的规则、所在规则集、动作、实际出站(节点 / 组 / 直连 / 拦截)、未命中时的兜底。域名目标按名字匹配,不做解析,所以只有 geoip 规则的域名会显示"未命中 → 兜底",这是预期:真实流量里它会先解析再按 IP 匹配。

## 10. 写规则的建议

1. 先放窄规则(具体域名、`ip`),再放宽规则(`geosite:cn`、`geoip:cn`),最后兜底。
2. 国内直连靠内置集就够了;想让国内流量走国内节点,先停用内置集里的两条 cn 直连规则。
3. 广告拦截用 `geosite:category-ads-all → 拦截`。
4. 不要把 `geoip:private` 删掉,它保证内网互访不进代理。
5. 改完用 Trace 和观测页的实时连接各看一眼;观测页「显示系统连接」关掉时只看设备流量。
